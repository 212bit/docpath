## 项目简要分析（只读勘察，未改动任何代码）

对 docpath 仓库做了一次结构与健康度勘察，结论要点：

- 定位：给 AI coding agent 用的「文档驱动 FSM 工作流 CLI」，v0.1.1，TS ESM + cac + tsup，node --test。
- 规模：src 148 个 .ts / 约 36.7k 行；tests 65 个 .mjs / 约 20k 行；templates 69 个 md；docs 15 篇。
- 分层：CLI 接入层（50+ 命令、register/ 拆 15 域）→ engine/（state-machine、transitions、breadcrumb、policy、workflow/lifecycle-profile）→ governance/（decisions ADR、continuation）+ hooks/ → .docpath/ 真源层（JSON/JSONL 机器真源，Markdown 人读视图）→ 安全层（dirty guard / worktree / session lock）。
- 自举程度高：.docpath/tasks/done/ 已积累 257 个完成任务，backlog 编号到 R-312（17 个在池、93 个已归档）。
- 当前工作流状态：state=completed / gate=review_pass / 分支 main；唯一未提交项是 `docs/design/refactor-doc-management-plan.md`（文档管理重构方案在途）。

发现的问题（未修，仅记录）：
1. `vite@6.3.5` 在 dependencies 中，但 src/ 全库零 import —— 疑似误加的运行时依赖。
2. `@types/prompts` 放在 dependencies 而非 devDependencies。
3. 同时存在 `@clack/prompts`（3 处引用）和 `prompts`（1 处引用）两套交互库。
4. 仓库根目录散落会话产物型 md：`COMPLETION-project-intake-security-fix.md`、`FIX-project-intake-concurrency.md`、`REVIEW-project-intake.md`、`docpath-evaluation.md`，与 docs/ 目录的归档约定不一致。

命令面：50+ 子命令，规模偏大；backlog 里 R-306~R-310 主题正是「仪式随规模缩放」，说明团队已意识到并正在收敛。
