# 架构分层与依赖防腐守卫 (Architecture Layers & Guardrails)

> DocPath 架构守卫体系通过代码级 AST 静态分析与依赖图拓扑扫描，
> 强制保障系统遵循严格的**单向依赖原则与无循环依赖架构不变量**。

---

## 1. 架构分层模型 (Layer Hierarchy)

DocPath 核心代码库由 6 个清晰分工的逻辑层级组成，自底向上单向依赖：

```text
┌────────────────────────────────────────────────────────┐
│  6. cli          (CLI 命令行入口与参数解析)              │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│  5. commands     (业务用例与命令编排层)                  │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│  4. governance   (多 Agent 协作、审批与继续治理层)       │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│  3. engine       (核心状态机、拓扑计算与工作流引擎)      │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│  2. utils        (通用纯函数、文件 I/O、Git 与日志工具)  │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│  1. types        (基础类型定义与数据契约)                │
└────────────────────────────────────────────────────────┘
```

## 2. 依赖合规矩阵与防腐规则

系统严禁反向依赖（如底层 `engine` 依赖上层 `commands`），也严禁跨层循环引用：

| 模块层级 | 允许导入的下层模块 | 严禁导入的上层模块 |
|---|---|---|
| **types** | 无（最底层纯契约） | `utils`, `engine`, `governance`, `commands`, `cli` |
| **utils** | `types` | `engine`, `governance`, `commands`, `cli` |
| **engine** | `types`, `utils` | `governance`, `commands`, `cli` |
| **governance** | `types`, `utils`, `engine` | `commands`, `cli` |
| **commands** | `types`, `utils`, `engine`, `governance` | `cli` |
| **cli** | 全部下层模块 | 无 |

## 3. 架构守卫体检命令 (`docpath arch check`)

DocPath 提供了开箱即用的架构体检工具：

```bash
docpath arch check
```

### 扫描与校验内容：
1. **模块依赖合法性**：扫描项目中全部 TypeScript/JavaScript 文件的 `import` 语句，对照分层合规矩阵进行校验。
2. **循环依赖探测 (Circular Dependency Detection)**：使用 Tarjan 强连通分量算法扫描全模块依赖拓扑，定位闭环路径。
3. **架构违规报告与阻断**：若发现越级反向导入或循环引用，输出精准的违规文件与行号，阻断任务收口。

---

## 4. 门禁集成与演进规范

- **开发期自查**：在进行较大规模模块重构时，随时运行 `docpath arch check` 确保架构纯洁。
- **CI / 质量门禁守卫**：`docpath check` 与 `docpath step-pass --commit` 已自动集成架构防腐校验。
- **重构引导**：若底层需要使用上层能力，必须采用**依赖倒置 (IoC)**、**事件驱动**或**回调参数注入**的方式解除耦合。
