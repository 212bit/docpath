## 背景

R-288 实施中发现 src/utils/changes-report.ts:152 存在 isDocpathWorktree 的完整重复实现，同样以「.docpath/backlog 与 .docpath/rules 是 symlink」识别 worktree——R-273 契约修正后永远 false，导致 changes --agent 的 worktree_isolation 报告整体成死功能（active 恒为 false）。

关键风险：不能只修判定复活该功能。isExpectedWorktreeIsolationNoise（changes-report.ts:158-166）的噪音分类仍停留在 symlink（live-shared）契约语义：把 worktree 内的 .docpath/backlog/、.docpath/rules/ 变更归类为「隔离噪音、非提交相关」。R-273 之后 backlog/rules 是 merge-mediated tracked copy，worktree 内的这些变更恰恰应该提交并随分支合并回 main；若仅修判定，报告会反向建议 agent 不提交应合并的 backlog 变更——R-271 家族（backlog 数据丢失）的行为模式。

## 提案

- 将 worktree 判定统一到与共享契约无关的机制（.git 为文件），与 R-288 在 git-dirty-guard.ts 的实现收敛为单一导出（消灭重复，而非各修一份）。
- 按 R-273 契约重写 isExpectedWorktreeIsolationNoise 语义：merge-mediated 资源（backlog/、rules/、tasks/done/）为 commit-relevant；isolated 运行时（workspace/、tasks/current/、journal/、docs.md 等 gitignored/派生物）为 noise。
- 为 worktree 内 changes --agent 的输出补契约一致性测试（backlog 变更必须出现在 commit_relevant_files）。

## 验收

- AC-1: 全仓库仅存一份 worktree 判定实现（grep 断言），在真实 linked worktree 内判定为 true。
- AC-2: worktree 内 changes --agent：backlog/rules/tasks-done 变更列为 commit-relevant，不再归类为 isolation noise。
- AC-3: isolated 运行时文件仍归类为 noise，现有 changes 测试全绿，新增契约一致性测试。
