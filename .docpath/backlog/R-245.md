## 背景

用户在 evoucher 需求讨论中发现 agent 仍会自由发挥。需要把需求梳理固化为 DocPath 正式 project-intake 工作流：原始材料捕获 -> 固定域分析 -> 缺口索引 -> 按对象澄清问题 -> 决策卡 -> 需求定稿 -> 拍板门 -> backlog guidance/种子。用户已确认方案 B：做成 DocPath 正式 intake 流程，而不是单项目文档。

## 验收

1. project-intake 文档/协议明确需求梳理阶段流水线和每阶段输出。2. next/status 或相关 project 命令能在 intake 阶段给出确定下一步，避免直接进入开发 backlog。3. 缺口索引、问题清单、决策卡、需求定稿、拍板门、backlog guidance 的职责边界被固化。4. 现有 project capture/analyze/brief/backlog 路径保持兼容。5. 有自动化测试或 CLI 快照验证新路由/输出。
