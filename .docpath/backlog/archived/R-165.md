## 背景

本次 R-164 dogfood 暴露出 DocPath 流程模型和证据模型的系统性问题：1. check 子任务完成度与 terminal verification step 形成自指死结，Agent 必须先把验证步骤标记 done 才能运行 check。2. pending-done 哨兵会在仍有 in_progress 或未完成步骤时劫持 next route，过早推荐 agent done。3. spec.json/plan.json 与 spec.md/plan.md 可能失步，读路径优先 JSON 时会读取旧上下文。4. review/check 统计类流水账仍可能污染 decisions.md。5. 被 git ignore 的 backlog/task evidence 在 changes/status 中不够显眼，团队提交时容易漏掉审计证据。

## 验收

1. 修复 check 与验证步骤自指死结：check 不再要求 terminal verification step 预先 done，或 plan 生成不再把 check/review/journal 作为业务步骤。2. 修复 pending-done 路由优先级：存在 in_progress 或未完成 plan step 时只警告，不推荐 agent done。3. 为 spec/plan JSON 与 Markdown 建立 stale/hash drift 检查，失步时 fail loud 并给出 tasks sync 修复命令。4. review/check 不再写入低价值 decisions.md 统计记录，并增加回归测试。5. status/changes 或相关 agent 输出能提示 ignored 的 backlog/task evidence 需要 git add -f。6. 补充覆盖上述流程问题的回归测试，并完成 docpath check/review/journal。
