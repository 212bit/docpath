## 背景

DocPath is a general development workflow state machine, not a default design process manager. Current UI design gate behavior is too broad because product UI wording can automatically enter the approval-gated UI flow. The agreed product decision is that UI design capability remains inside DocPath as an evidence-backed optional quality layer, but it must not be part of the default development flow.

## 验收

AC-1: Generic UI or frontend wording such as page, layout, component, dashboard, CSS, or frontend implementation does not automatically set ui_gate required. AC-2: Explicit design intent such as UI design, UX analysis, visual direction, prototype, Figma, v0, Stitch, Framer, design-preview, or design approval sets ui_gate required. AC-3: Existing explicit required or exempt declarations remain authoritative and no historical migration is performed. AC-4: Unknown UI-related tasks may emit non-blocking advisory output but do not fail go or check. AC-5: When explicitly required, go still enforces the minimal design approval set and check still enforces full design and visual acceptance evidence. AC-6: write-design remains a DocPath evidence writer and is not a workflow trigger. AC-7: docpath-design skill and generated templates describe explicit opt-in behavior.
