# 修复开发前分析能力的 MVP 窄化问题

## 背景
上一轮新增了 `docpath analyze` / `docpath write-analysis` / predev-analysis skill，用于开发前需求、产品、UI、技术影响分析。但实现存在 MVP 取舍过窄：核心产物落为单一 `analysis.md`，不利于后续 UI/产品/技术 skill 分别更新；命令和文档也围绕单文件模型设计。

## 目标
审计并修复 predev-analysis 能力中不利于长期演进、skill 分工协作和工作流集成的窄化点。

## 验收
- 支持结构化分析目录，例如 `analysis/requirements.md`、`analysis/product.md`、`analysis/ui.md`、`analysis/technical.md`、`analysis/index.md`，并保留旧 `analysis.md` 兼容入口或迁移说明。
- `write-analysis` 支持按 section 写入/更新，避免 UI/产品/技术 skill 相互覆盖。
- `analyze` 输出明确区分需求/产品/UI/技术分析，并说明推荐写入命令。
- `refine`/`plan` 或相关上下文读取能发现结构化 analysis 产物，而不是只依赖单文件。
- Codex skills、安装产物、测试和文档同步更新。
- 运行相关测试、build、check、review，并完成归档。
