## 背景

目标: 将现有 DocPath dashboard 从只读 API + 轻量页面升级为可用的本地前端信息面板，支持多项目查看，用于展示每个 DocPath 工作区的状态、next route、backlog、当前/历史任务、gate/check/review、消息/事件流。已验证事实: 项目已有 docpath dashboard 命令、React/Vite dashboard UI、build:dashboard 脚本、dashboard-dist 发布入口、只读 API /api/projects /api/state /api/checks /api/review /api/backlog，以及 Dashboard/Tasks/Gates/Backlog 页面。多项目基础也已存在: src/engine/project-registry.ts 使用本地 SQLite 记录通过 docpath init 注册过的项目，支持 DOCPATH_REGISTRY_DB 覆盖；dashboard API 已能列出 /api/projects，并通过 root query 参数读取已注册项目或当前 cwd。核心用户: 同时维护多个 DocPath 项目的 operator/agent，需要在一个本地 dashboard 中快速比较哪些项目有活跃任务、哪些项目阻塞、哪个 backlog 最值得推进，以及每个项目当前下一步是什么。MVP 范围: 保持本地只读 dashboard；支持跨项目总览、项目切换、单项目钻取、项目级 health/next/action/backlog/tasks/events；优先补齐 next route/health、task detail、backlog filtering/detail、event/message timeline、loading/empty/error/stale project 状态；暂不做浏览器里执行 docpath 命令、写入 backlog、注册/删除项目、多人权限系统或远程服务。产品假设: 第一个版本面向本地开发者和 agent 操作者，不面向公网部署；多项目来源以本地 registry 为准，当前启动 cwd 即使未注册也应作为 local project 可见。设计要求: 管理工具风格，信息密度高、可扫描、少装饰；需要设计 brief、preview、approval 后才能写产品 UI 代码。技术方向: 复用现有 dashboard command 和 React UI；扩展只读 API，从现有 project registry、workspace JSON/JSONL 和必要的 CLI summary 派生结构化数据；保持 GET/HEAD only，不引入写操作。主要风险: 多项目聚合若逐项目读取大量文件会慢；已注册项目可能被移动/删除；不同项目 DocPath 版本/schema 可能不一致；直接解析人类 Markdown 会脆弱；事件流若读取完整 breadcrumb.jsonl 可能过重；若加入命令执行会扩大权限边界。

## 验收

MVP 可验收条件: 1. docpath dashboard 启动后能显示全局多项目总览: 项目数、活跃任务数、阻塞项目数、最近失败 gate、install health/registry health 摘要。 2. 当前启动 cwd 即使不在 registry 中也作为 local project 可见；已注册项目按 last_seen_at/name 排序展示，并标识 stale/unavailable/unknown schema。 3. 项目切换后，首页能展示该项目的 phase/gate/current step、next action/recommended command、install health 和最近 gate 状态。 4. Backlog 页面支持按项目查看，并支持状态/优先级/成熟度筛选、搜索、列表和详情摘要；跨项目总览能显示各项目 backlog counts。 5. Tasks 页面能展示每个项目的当前任务、已完成/阻塞步骤、canonical/current 任务关系和最近更新时间；跨项目视图能按 blocked/active/completed 分组。 6. Messages/Events 页面或区域能展示所选项目近期 breadcrumb/session/check/review 事件，并限制读取量；跨项目视图只显示摘要，不一次性拉取所有长日志。 7. UI 覆盖 loading、empty registry、unknown project root、deleted project、partial data、permission/read error、mobile/desktop 响应式。 8. API 保持只读，无命令执行 endpoint；root 参数只能读取当前 cwd 或 registry 中项目，避免任意路径读取。 9. 测试覆盖多项目 registry API shape、unknown root 拒绝、stale project 容错、只读保护、关键页面构建。 10. UI brief、design preview、design approval 完成后才进入实现。
