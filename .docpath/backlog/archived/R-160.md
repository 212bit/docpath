## 背景

当前产品定位已从“企业级审计合规层”收敛为“多人 / 多 Agent 团队的 AI 工作流状态层”。需要将这次定位结论沉淀为可执行的产品方向，明确 CLI/FSM/check/review/breadcrumb/handoff 在团队协作语境下的价值，避免后续路线图继续向过重的企业合规能力漂移。

## 验收

1. 产出一份产品定位说明，清晰定义目标用户为多人开发团队、多 Agent 协作团队和需要交接恢复的 AI 开发场景。
2. 明确非目标：暂不做完整 RBAC、SSO、法务审计报表、不可篡改账本、多租户企业控制台等企业合规平台能力。
3. 将现有能力用团队协作语言重新解释：共享状态、可交接、可校验、可恢复、决策不漂移。
4. 重排路线图：P0 聚焦交接、恢复、任务归属、门禁可见；P1 聚焦多 Agent 隔离、冲突检测、团队状态视图；P2 聚焦 prompt 标准化、自然语言入口和错误解释。
5. 给出后续可拆分的实现任务建议，但不在本任务直接进入代码实现。
