# Decision Brief: 风险分级门禁 + 仪式文档自动化 + CLI 端验证收口

## 背景

现状：门禁强度由 `workflow_profile`（quick/standard/strict/instant）× 复杂度级别（L0–L3）静态决定，唯一的风险信号是 `quick-guard.ts` 的路径黑名单（仅用于拒绝 quick 升级）。随着宿主模型能力持续增强，"流程阶段"作为门禁强度的依据正在贬值：强模型能一次做对小任务，阶段仪式反而成为成本；而真正决定出错代价的是任务风险（契约变更、迁移、CI/CD、核心引擎改动）。

## 方向（三支柱）

### 1. 门禁强度与任务风险挂钩（而非与流程阶段挂钩）

- 引入任务级风险维度 R0–R3，在 `backlog promote` / `quick` 创建时评估，依据：触碰路径类别（扩展现有 `RISKY_PATH_PATTERNS`）、契约/API/schema 变更、迁移/CI/CD、影响面（文件数）。
- 门禁策略从 profile 静态查表改为 `risk × level` 的函数（扩展 `workflow-profile.ts` 的 `PROFILE_POLICIES`）。
- 风险在 closeout 前按实际 diff 复评：沿用并泛化现有 quick→standard 自动升级机制（`check.ts` 已有先例），R 级别只能升不能降。
- 现有 `major_change_gate` / `ui_gate` / `resolveEffectiveWorkflowProfile` 是自然扩展点。

### 2. 仪式性文档产出自动化

- spec：由 backlog 背景/FR/AC + 模板确定性播种（promote 已部分支持），agent 增量编辑而非从零撰写；L1 任务 spec 完全自动生成、agent 只确认。
- plan：扩展 `renderDraftPlan` 的确定性草稿生成 + FR/AC 覆盖断言为标准任务的默认路径，agent 做语义精化而非结构创作。
- journal：ADR 候选提取改为 propose-only + 自动轮转，agent 只做取舍。

### 3. "可验证"永远留在 CLI 侧

- 阻断性判定只来自确定性校验器；模型评审（review skill）保持 advisory 或需显式 `--skip --reason`（维持 `review-skill-router` 现状）。
- 为 risk × gate 矩阵建立不变量测试，使"风险越高门禁越强"成为可测试断言。

## 分期建议

- 包 1（引擎）：风险模型 + `risk × level` 门禁策略 + check 期风险复评升级。
- 包 2（文档自动化）：spec 播种、plan 草稿默认化、journal 提取 propose-only。
- 包 3（收尾）：接线或移除未使用的 `engine/escalation.ts`；门禁矩阵不变量测试。

## 边界与不做的事

- 不改变现有四档 profile 的对外命令名与兼容性（表内重排而非 API 破坏）。
- 不引入 LLM 到 CLI 进程内（维持确定性原则）。
- 风险评估初版为启发式规则，预留 config 覆盖（沿用 `quick:` 配置块模式）。

## 备选方案

- 方案 B：仅扩展现有 quick/standard 二分，不引入 R 维度 —— 落地快但无法表达"高风险小任务"与"低风险大任务"，半途而废。
- 方案 C：把门禁判定全部交给宿主 agent 自评 —— 违反"验证不归执行者"原则，放弃。

## 任务范围

本任务（R-338 promote 后）范围 = **包 1（引擎）**：风险模型 + risk × level 门禁策略 + check 期风险复评升级。包 2（文档自动化）与包 3（escalation.ts 处置 + 矩阵测试收尾）在包 1 落地后另立条目。

## 验收

- AC-1: 引入任务级风险维度 R0–R3，由确定性规则在任务创建时评估（触碰路径类别、契约/API/schema/迁移/CI 触碰、影响面），规则可经 `.docpath/config.yaml` 覆盖，风格沿用现有 `quick:` 配置块模式。
- AC-2: 门禁策略由 profile 静态查表改为 `risk × level` 函数；quick/standard/strict/instant 四档对外命令名与兼容性不变。
- AC-3: check 期基于实际 diff 复评风险，风险只升不降；升级走现有 quick→standard 自动升级机制的泛化路径，并留下审计记录。
- AC-4: risk × gate 矩阵存在不变量测试（高风险任务的门禁强度 ≥ 低风险任务）。
- AC-5: 现有测试套件全绿，`docpath check` 门禁通过。
