## 背景

DocPath 当前能通过 brainstorm/refine/write-spec 生成规约，也能通过 discover 探测项目，但缺少开发前的系统化准备阶段：需求分析、产品/用户场景分析、UI/UX 分析、技术影响分析与决策记录。用户明确指出：开发前准备能力不足，尤其需求分析和 UI 分析缺口明显。

## 目标

在进入 spec/plan/实施前，提供一个可被 Agent 调用的 predev analysis 能力，把模糊需求先整理成可检查的分析文档，再由分析结果生成 spec 或进入计划。

## 建议范围

- 新增开发前分析模板，覆盖 Requirements、Product、UI/UX、Tech Impact、Risks、Decisions、Open Questions。
- 新增/扩展 CLI 命令或 prompt-only 能力，让 Agent 能生成 `.docpath/tasks/current/analysis.md`。
- 将 analysis 纳入 Agent 集成文档与 skills，使需求分析/UI分析在 spec 前被明确触发。
- 增加 doctor/check 或 plan 前提醒，避免复杂任务跳过分析。

## 验收

- 复杂/含 UI 的需求有明确方式生成 analysis.md。
- analysis.md 可作为 write-spec/refine 的输入或上下文。
- CLI 帮助、测试、文档体现该能力。
- 不破坏现有 brainstorm/refine/spec/plan/go/run 流程。
