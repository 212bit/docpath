## 背景

另一 agent 已确立「顶层接口聚合、底层机制解耦」原则：`docpath done` 内部即 `check -> review -> journal` 完整门禁序列，因此面向用户的推荐应是**一步到位的复合命令**，`check` / `review` 降级为「中途自测 / 单独排查」的原子工具。

已完成的对齐（基准）：`src/utils/closeout-route.ts`、`src/utils/agent-output/formatters.ts`（3 个分支）、`AGENTS.md` + 模板 + protocol blocks。

本次为**第一批低风险对齐**：把上一轮排查中「文案层」的残留点补齐（不涉及门禁契约层与新增命令）。均为纯文案改动，改法与基准一致。

1. `src/commands/worktree/query.ts` 的 `suggested_action` 不再输出三连，改为推荐 `docpath done`（并统一箭头写法）；
2. `src/commands/check.ts` 通过后的下一步引导改为 `docpath done`，并保留「单独排查可运行 docpath check」的语义；
3. `src/commands/check/evidence.ts` 在 `check.passed` / `check.env_exempt` 事件写入的 `currentStep` 文案改为指向 `docpath done`；
4. `src/commands/task.ts` reopen 后的闭环提示改为 `docpath done`；
5. `src/utils/closeout-route.ts` 文件头注释与已改实现（第 56 行已推荐 `docpath done`）一致；
6. 相关既有测试更新且全量 `docpath check` 通过；改动不触及门禁合法性判定逻辑（`isWorkflowGateCommandAllowed` 等）。
