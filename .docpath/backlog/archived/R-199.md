## 背景

Sentinel flow-runner release/development exposed four DocPath workflow friction points: quick closeout counts tracked .docpath/workspace runtime files toward the guarded non-DocPath file limit and can block tiny README-only tasks; manual rollback of workspace runtime files can create task identity drift between state, sessions, and current/canonical task files; backlog promote can omit explicit UI design gate defaults so pure CLI/script tasks are blocked at go --step; direct Markdown edits to spec.md/plan.md do not update spec.json/plan.json machine truth and next continues to report stale missing context. These issues increase recovery cost for small documentation, packaging, and CLI tasks.

## 验收

Decision Brief confirms scope and compatibility rules. Quick closeout ignores DocPath-owned runtime/status files or gives a recovery path that does not require unsafe workspace rollback. Task identity drift diagnostics recommend canonical repair paths without locking normal recovery. Promoted specs include explicit UI design gate defaults or unambiguous non-UI classification for CLI/script tasks. Markdown/JSON machine-truth divergence is detected or surfaced with actionable write-spec/write-plan guidance. Automated tests cover the changed gate and recovery behavior where practical.
