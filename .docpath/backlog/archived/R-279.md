## 背景

R-277 实证 (2026-07-17): 本地 CLAUDE.md 承载 R-269/R-273 用户确认修正, 模板是
R-271 致 P0 旧契约; install --check 只报"本地改动 1 项", install_health 自
2026-07-10 长红, recommended_command=docpath install 若被执行会用旧模板覆盖修正。
机制: countLocalAssetDrift (install-core.ts) 只比 local vs manifest sha, 不知道
模板现在长什么样; 而 detectInstallAssetDrift 已调用 buildExpectedInstallAssets
渲染出全部模板 expected sha——三方判定的材料齐全, 只缺分类与方向化建议。

## 需求

- FR-1: modifiedLocal 逐项三方向分类 (local sha vs expected sha vs manifest sha): local==expected → manifest_stale (本地已与模板一致, 重装仅刷新 manifest, 无覆盖风险); local≠expected 且 expected==manifest → local_ahead (模板自安装未动, 本地承载修正——提示先 diff 回灌模板再重装, 明确警示直接 install --force 会丢失本地修正); 双不等 → diverged (双向漂移, 人工比对合并)。
- FR-2: install --check 失败输出按方向分组列出文件与各自建议命令, 替换现有单一"建议运行 docpath install"。
- FR-3: install_health (next/status agent 输出) 的 recommended_command 方向化: 存在 local_ahead/diverged 时不再推荐直接 install, 改为提示 diff 回灌路径; 仅 manifest_stale/template_ahead 时维持 install 建议。
- FR-4: AGENTS.md 等豁免资产维持现状 (不参与 modifiedLocal, 不受本条影响)。

## 验收

- AC-1: 构造三种方向的临时工作区, install --check 输出各自方向标签与对应建议; local_ahead 场景输出含"回灌模板"警示且不推荐直接覆盖。
- AC-2: install_health 在 local_ahead 场景的 recommended_command 不是覆盖式 install。
- AC-3: 既有 31 条 install 用例回归; pnpm test 全绿。
- AC-4: R-277 修复后的当前仓库 install --check 仍通过 (无回归)。

## 范围

不包含: install --force 对豁免资产的覆写行为 (R-278); 自动回灌/三方合并的实现 (仅诊断与建议); doctor 命令的对应改造 (如需另立)。
