## 背景

Retrospective from the 2026-07-15 worktree development run found that the current worktree guidance and flows are too Codex-specific and leave several agent workflow gaps: session naming is codex-bound, worktree create cannot target an intended backlog item, closeout is spread across multiple commands, dirty guards can block current-task evidence, write-spec can confuse phase during execution, doctor does not surface git worktree index permission issues clearly, and stacked worktrees need clearer base/merge readiness metadata. The user confirmed the direction and explicitly wants future multi-tool compatibility rather than Codex-only assumptions.

## 验收

1. Worktree docs/protocols use agent-neutral language by default, with Codex/Claude/OpenCode examples treated as adapters rather than the primary contract. 2. Session-id guidance supports DOCPATH_SESSION=<tool>-<backlog-id>-<slug> without requiring codex in the name. 3. A concrete implementation plan exists for worktree create --backlog/--base, doctor metadata, and closeout readiness, with compatibility risks called out. 4. The change does not disturb active task R-267 and is developed in an isolated worktree before merge.
