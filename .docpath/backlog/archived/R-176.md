    - 当前问题: Agent protocol 要求启动时连续运行 `docpath status --agent` 和 `docpath next
    --agent`，但两者 agent 输出主体高度重复，导致恢复流程冗余。

    - 目标: 将启动/恢复默认入口收敛为 `docpath next --agent`，同时保留 `docpath status --agent`
    的诊断角色。

    - 背景: 用户观察到两个命令返回相同字段，并明确要求“修改 agent protocol，把双命令启动改成单命令启动”。

    - 可选方案: 继续双命令；合并 status/next；保持两个命令但协议默认只调用 next。

    - 推荐方案: 保持两个命令兼容，协议默认只调用 `docpath next --agent`；仅在显式状态查看、调试漂移或状态变更后确认时调用
    `docpath status --agent`。

    - 不做什么: 不删除 `status --agent`；不改变 `next --agent`/`status --agent`
    的结构化输出兼容字段；不把 status 从 install 配置中移除。

    - 成本: 需要同步协议文件、安装模板、Codex skill 模板、handoff 文案和测试断言。

    - 回滚方案: 恢复协议模板中的 First Steps/Required Route 文案为 status+next 双命令，并回退 handoff
    文案与测试断言。
