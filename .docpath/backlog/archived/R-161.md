## 背景

DocPath 已明确定位为多人 / 多 Agent 开发团队的 AI 工作流状态层。当前 handoff 已能生成可恢复上下文，但需要进一步围绕团队接力场景强化：下一个人或下一个 Agent 应能从 handoff 中直接看到当前任务位置、下一步推荐、验证状态、剩余风险、修改范围和阻塞原因。该任务是多人团队定位下的 P0 协作闭环能力，不涉及企业权限、SSO、审计报表或多租户控制台。

## 验收

1. `docpath agent handoff` 输出必须包含下一步推荐、剩余风险、验证状态、修改范围和接手提示。
2. handoff 内容必须引用或汇总 `current`、`breadcrumb`、`last-check`、`review` 和当前任务计划。
3. 当 check/review 未通过或缺失时，handoff 必须明确标出阻塞状态，不能给出“可继续完成”的暗示。
4. handoff 文案使用团队协作语言，服务“下一个人 / 下一个 Agent 接手”，而不是单纯压缩上下文。
5. 增加或调整测试覆盖 handoff 的关键字段、通过态输出和阻塞态输出。
6. 不引入完整权限模型、多 Agent 自动编排、企业审计报表或 Web 控制台。
