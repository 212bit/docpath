## 背景

Dogfooding R-199 exposed that `docpath plan` can write a generic two-step plan such as "clarify scope" and "implement feature" for a Level 3 workflow-change task, then advance workflow state as if a durable execution plan exists. This violates the prompt-emitter versus artifact-sink boundary and risks building the rest of the workflow on a low-quality plan.

## 验收

Decision Brief confirms command-contract behavior. `docpath plan` no longer persists or advances workflow state when it only has a generic prompt/preview plan. Durable plan writes require current-session generated content through `docpath write-plan --stdin`, or `docpath plan` must fail loud unless it can produce a structured, specific plan meeting minimum quality checks. Tests cover generic-plan rejection, state preservation, and valid write-plan persistence.
