## 背景

2026-07-16 review R-271 实现 (ef1be38) 时在 scratch 仓实测复现完整数据丢失链:
(1) 本仓 backlog/*.md 被 git track (R-238 Option B 有意决策, 7b3f9f0);
(2) R-271 按过时 CLAUDE.md (仍写 live-shared/gitignored) 强制把 tracked 的
.docpath/backlog 换成 symlink → worktree 内全量文件显示 deleted + 未跟踪 symlink;
(3) git add -A (agent 惯用 / worktree merge FR-2 自动提交) 把删除+symlink blob 记入提交;
(4) 合回 main 后 backlog/*.md 被删除, .docpath/backlog 变成悬空 symlink。

考古: 6/19 (80ef439) Option C untrack 落地过 → 6/30 R-238 用户确认翻回 Option B
(merge-mediated, stay tracked) → R-271 未引用 R-238、基于过时文档再翻回 symlink。
根因是契约三方打架 + CLAUDE.md 未随 R-238 更新。

## 决策 (2026-07-16 用户确认)

方案 B: 回滚 R-271 的强制 symlink, backlog 共享契约最终定为 R-238 Option B
(merge-mediated tracked 副本)。stale 快照降级为已知限制 (merge 收敛)。
R-271 的 id 撞号动机改由跨 checkout 分配器解决。

## 需求

- FR-1: worktree create/repair 撤销 forceLiveShared, backlog 回到 tracked → 目录副本分支; 现存 symlink 形态的 backlog 经 repair 转回副本。
- FR-2: worktree doctor 对 backlog 回到 merge-mediated 检查; symlink 形态报 FAIL 引导 repair (与 R-271 反向)。
- FR-3: backlog id 分配跨 checkout: 在 worktree 内 capture/add 时, 经 resolveWorktreeManagerRoot 同时扫描 main checkout 的 backlog/ 与 backlog/archived/, 取全局 max+1; 非 worktree 行为不变。
- FR-4: CLAUDE.md worktree 章节更正为 Option B 真相 (backlog merge-mediated tracked; id 单池在 CLI 层; stale 快照已知限制), 消除导致 R-271 误判的文档漂移。
- FR-5: 归档的 R-271 条目补 superseded-by R-273 注记; 决策日志记录契约最终裁定 (R-273 覆盖 R-271 symlink 契约, 恢复 R-238)。

## 验收

- AC-1: scratch 仓 tracked backlog + worktree create → backlog 为目录副本, git status 无 backlog 删除噪声; 复现链 (add -A + merge 回 main) 不再删除 main backlog。
- AC-2: doctor 对副本 backlog pass, 对 symlink backlog fail; repair 把 symlink 转回副本。
- AC-3: worktree 内 capture 分配 id = max(本地, main 池)+1, 不与 main 撞号; 非 worktree 分配行为不变。
