## 背景

2026-07-16 代码核验 (analysis: .docpath/backlog/analysis/R-276-analysis.md):
三事实叠加成完整绕过链——F1 review 默认 scope='all' 仅审工作区, 树干净即
not_required (R-274 实测); F2 commit-first 收口惯例被重大变更门禁信号设计鼓励,
语言级审查被系统性绕过; F3 done 复用纯 60min 时间窗不绑 HEAD, review 后再提交
不触发重审。task 口径 (started_at 以来提交∪工作区, baseRef=任务首提交^) 已在
review.ts 完整实现但 CLI 枚举未放行, router 指纹 task 分支用全历史与之不一致。
用户已裁定: 方案 A + 复用绑定 HEAD 加固。

## 需求

- FR-1: review 默认口径——有活跃任务且 started_at 可解析时默认 scope='task', 否则回退 'all'; 显式 --scope 仍优先。
- FR-2: CLI 枚举放行 task——register/quality.ts 的 review --scope 与 write-review-skill --scope 接受 task 并更新帮助文案。
- FR-3: router 指纹对齐——review-skill-router.ts diffForFile(task) 从 git log --follow --patch 全历史改为 baseRef..HEAD + 工作区 (与 review.ts 同口径), baseRef 由调用方解析传入。
- FR-4: 复用绑定 HEAD——ReviewEvidence 增加 head 字段 (append-only); review 写证据时记录当前 HEAD; canReuseReviewGate 在 evidence.head 存在且 ≠ 当前 HEAD 时拒绝复用; 旧证据无 head 维持时间窗判定 (向后兼容)。

## 验收

- AC-1: 活跃任务内树干净但任务有提交时, docpath review 的 router requirements 覆盖任务累计 diff 的 TS/JS 文件, 不再 not_required。
- AC-2: 无活跃任务 (或 started_at 缺失) 时 review 行为与现状一致 (scope=all)。
- AC-3: router 指纹 task 口径与 review.ts 一致——同一任务同一 git 状态下指纹稳定, 新提交后指纹变化。
- AC-4: review 后新提交 ⇒ done 拒绝复用并重审; 无 head 字段的旧证据仍按时间窗复用。
- AC-5: pnpm test 全绿; write-review-skill 在 task 口径下走通 (指纹/文件集匹配)。

## 范围

不包含: check 复用的 HEAD 绑定 (last-check 证据, 如需另立); 重大变更门禁口径调整 (机制独立, 维持现状); review 发现项的行级基线细化。
