## 背景

2026-07-16 review R-271 实现 (ef1be38) 时 scratch 仓实测复现完整毒链: (1) 本仓 backlog/*.md 实际被 git track (先于 ignore 规则提交); (2) worktree create 强制把 tracked 的 .docpath/backlog 换成 symlink → worktree 内全量文件显示 deleted + 未跟踪 symlink; (3) agent 惯用 git add -A 或 worktree merge FR-2 自动提交会把删除+symlink blob 记入提交; (4) phase=completed 后合回 main (worktree merge 或文档标准路径 git merge): main 的 backlog/*.md 被删除, .docpath/backlog 变成指向 ../../../.docpath/backlog 的悬空 symlink。测试未覆盖: worktree 测试夹具的 backlog 未 track。修复方向 (择一或组合): (a) 根治—main 侧 git rm --cached 解除 backlog 跟踪 + 补 .gitignore, 使 symlink 替换零噪声 (对齐 option C 原意); (b) create/repair 时对 backlog 路径 git update-index --skip-worktree; (c) worktree merge FR-2 的 add -A 排除 ':!.docpath/backlog'; (d) merge 前检测提交含 backlog 删除即拒绝。次级问题: worktree repair 对非 symlink 副本直接 rm -rf, 本地未同步的新 capture 会被销毁, 替换前应把 local-only 条目并入 main。在第一个新 worktree 走完 completed 合回之前必须修复。
