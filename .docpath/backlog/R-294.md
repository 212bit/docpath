## 背景

2026-07-26 架构 review 定性的配置双真源：readDocPathConfig（src/utils/config.ts:17-34）只读 .docpath/config.json，而 init 只写 config.yaml——经 json 读取器消费的新字段永远看不到 init 写入的值（rules gotcha 记录的 S5 事故类）。目前仅 readDeclaredDocumentScanPaths 打了 yaml 优先补丁，形成「按字段各选真源」。全仓库审计（2026-07-26）：config.json 直接读取仅剩 readDocPathConfig 一处，其余消费方（trace/stats/config 命令/brainstorm/resume/quick-guard/project-registry）均已 yaml 化——修复面集中单函数。

## 提案

readDocPathConfig 统一为 yaml 优先 + json 回退的单一出口：

- 读 config.yaml（parse）与 config.json，按顶层字段浅合并，冲突 yaml 胜——采纳 rules 既定惯例（"消费方优先用 parse 读 config.yaml，需要兼容时回退 config.json"，quick-guard/project-registry/scan-paths 三处现行 idiom）。
- json 独有字段（artifacts、review_skill_gate 等历史配置）继续生效（回退填充），兼容边界不破。
- readDeclaredDocumentScanPaths 的字段级 yaml 补丁随之退役，改走统一出口（语义等价：yaml 声明优先、json 回退、未声明返回 null）。
- 不迁移文件、不删 config.json、不改写方（init 仍写 yaml，config 命令仍管 yaml）。

## 验收

- AC-1: yaml 与 json 并存时，顶层同名字段 yaml 胜；json 独有字段仍可见；yaml 独有字段（init 写入类）经 readDocPathConfig 可见（S5 事故类根除）。
- AC-2: readDeclaredDocumentScanPaths 行为不变（既有测试全绿），实现改走统一出口、无字段级特判。
- AC-3: 仅 config.json 存在（历史工作区）行为完全不变；review_skill_gate/artifacts 既有 fixture 测试全绿。
