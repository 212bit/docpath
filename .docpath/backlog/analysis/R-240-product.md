# R-240 产品分析 (product)

## 1. 用户价值与痛点

### 当前痛点
| 角色 | 痛点 | 严重度 | 频率 |
|---|---|---|---|
| Agent（新会话） | `reveal --topic X` 展示最近 5 条 ADR 而非与 X 相关的 ADR → 看不到历史决策，可能重复争论已定设计点 | 中 | 每次涉及已有设计点的会话 |
| Agent（新会话） | `context --topic X` 完全不展示 ADR → 决策历史对上下文消费不可见 | 中 | 同上 |
| Agent（收尾） | journal ADR 提取的 breadcrumb 双正则（最低优先级兜底层）命中率低 → 无 brief/决策表的任务 ADR 丢失 | 低 | 仅无 brief 的任务 |
| 人类开发者 | §2.2 宣称"新 API 契约""自动归档""高精度检索"与实际不符 → 误导对能力的预期 | 低 | 读文档时 |

### 价值判断
- **核心价值**：让"防止漂移"从被动变主动——Agent 触碰设计点时自动看到历史 ADR。
- **次要价值**：文档准确性对齐，消除过度宣称。
- **低价值/不做**：不实现"新 API 契约"自动提取（删宣称即可）；不引入向量检索。

## 2. 成功指标

| 指标 | 当前基线 | 目标 | 度量方式 |
|---|---|---|---|
| reveal 主题相关 ADR 命中率 | 0%（展示最近 5 条，非主题匹配） | 有相关 ADR 时 >80% 命中 | 手动测试：对已知有 ADR 的主题执行 reveal |
| context 主题相关 ADR 命中率 | 0%（完全不展示） | 有相关 ADR 时 >80% 命中 | 同上 |
| §2.2 宣称-实现对齐度 | 4 处差距（证据表） | 0 处差距 | 逐条核对 |
| ADR 提取覆盖率（有 brief 的任务） | 已有 brief 提取（一级优先） | 维持，无退化 | 回归测试 |

## 3. 影响范围

- **直接影响**：`reveal.ts`、`context.ts`、`docs/product-panorama.md §2.2`
- **间接影响**：`decisions.ts`（可能需要新增按主题查询函数）
- **不影响**：`journal.ts`（ADR 提取三级链已就位）、`decisions.jsonl` schema、dashboard UI
