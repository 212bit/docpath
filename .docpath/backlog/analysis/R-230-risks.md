# DocPath UI Design - Risks Analysis

## 1. 产品风险

### 风险 1.1：用户不适应新配色（中等）
- **描述**：从深色 Obsidian 主题切换到温暖浅色主题，部分用户可能觉得刺眼或不适应
- **影响**：用户体验下降，可能降低 Dashboard 使用率
- **概率**：30%
- **缓解措施**：
  - 保留主题切换功能（dark/light/warm）
  - 在版本发布说明中提前告知变更
  - 收集用户反馈，考虑提供"经典深色主题"选项

### 风险 1.2：信息密度变化影响效率（低）
- **描述**：温暖设计可能增大组件间距和字号，导致单屏信息量减少
- **影响**：需要更多滚动操作，效率略降
- **概率**：20%
- **缓解措施**：
  - 保持合理的信息密度，避免过度"呼吸感"
  - 通过用户测试验证关键页面的信息可见性

## 2. 设计风险

### 风险 2.1：Terracotta 强调色对比度不足（中等）
- **描述**：#C4612F 在浅色背景上的对比度可能不满足 WCAG AA 标准（需 4.5:1）
- **影响**：可访问性不达标，色盲用户体验差
- **概率**：40%
- **缓解措施**：
  - 提前使用 WebAIM Contrast Checker 验证
  - 如不达标，调整为更深的 #A94E22（hover 色）或增加边框/背景辅助
  - 关键操作按钮使用高对比度的深色文本

### 风险 2.2：Serif 字体在小字号下可读性差（低）
- **描述**：Fraunces/Georgia 等 serif 字体在 12px 以下可能有锯齿或模糊
- **影响**：长时间阅读疲劳
- **概率**：15%
- **缓解措施**：
  - 仅在大标题（h1/h2）使用 serif，正文保持 Inter
  - 设置最小字号为 14px
  - 启用 `text-rendering: optimizeLegibility`

### 风险 2.3：组件库不完整导致视觉不一致（中等）
- **描述**：改造时可能遗漏某些页面或状态，导致新旧风格混杂
- **影响**：用户困惑，品牌形象受损
- **概率**：25%
- **缓解措施**：
  - 制作组件清单（Badge/Button/Card/Panel/Table/Modal）
  - 逐页核对，确保所有交互状态都已覆盖
  - 代码审查时检查 `className` 是否还引用旧变量

## 3. 技术风险

### 风险 3.1：Tailwind 4 @theme 语法不兼容（低）
- **描述**：Tailwind CSS 4 是相对新的版本，可能有未知 bug
- **影响**：构建失败或样式渲染异常
- **概率**：10%
- **缓解措施**：
  - 在改造前运行 `pnpm run build:dashboard`，确认现有配置可用
  - 查阅 Tailwind 4 官方文档，遵循最佳实践
  - 必要时降级到 Tailwind 3

### 风险 3.2：字体 CDN 加载失败（低）
- **描述**：Google Fonts 在某些网络环境不可达（防火墙/离线）
- **影响**：字体降级到系统 serif，视觉效果打折
- **概率**：10%
- **缓解措施**：
  - 使用 `font-display: swap`，避免阻塞渲染
  - 提供系统字体降级链：`Fraunces, Georgia, 'Times New Roman', serif`
  - 文档中说明如何配置本地字体文件

### 风险 3.3：CSS 变量覆盖导致旧组件失效（中等）
- **描述**：修改 `--color-accent` 等变量后，某些硬编码颜色的组件可能显示异常
- **影响**：部分页面颜色错误
- **概率**：20%
- **缓解措施**：
  - 全局搜索 `#7c6af7`（旧 accent 色），替换为变量引用
  - 使用浏览器 DevTools 逐页检查颜色是否正确
  - 编写简单的 CSS Lint 规则，禁止硬编码颜色

## 4. 交付风险

### 风险 4.1：设计改造时间被低估（高）
- **描述**：7 个页面 + 所有交互状态改造可能需 20+ 小时，而非预期的 10 小时
- **影响**：延期或质量妥协
- **概率**：50%
- **缓解措施**：
  - 优先改造核心页面（Overview + Workboard），其他页面可分阶段
  - 使用 MVP 策略：先完成 P0 需求（配色 + 核心组件），P1 需求（插图/动画）可延后
  - 设置时间 buffer：计划 12 小时，实际预留 18 小时

### 风险 4.2：缺乏设计审查导致返工（中等）
- **描述**：改造完成后用户/团队不满意，需大幅返工
- **影响**：浪费时间，士气受挫
- **概率**：30%
- **缓解措施**：
  - 在改造前输出设计稿（Figma/截图），获得确认
  - 改造第一个页面（Overview）后暂停，邀请审查
  - 设置"不超过 2 次大返工"的原则，避免无限迭代

## 5. 缓解措施与触发条件

### 主动缓解（现在执行）
1. **对比度验证**：使用 WebAIM 工具验证所有颜色对
2. **组件清单**：列出所有需改造的组件和状态
3. **主题切换开关**：在代码中预留 `theme` 切换逻辑

### 被动监控（上线后）
| 指标 | 阈值 | 触发动作 |
|------|------|----------|
| Lighthouse Accessibility 得分 | < 90 | 修复对比度/语义化问题 |
| 用户反馈"太亮/不适应" | > 3 次 | 发布深色主题补丁 |
| CSS 文件体积 | > 100KB | 优化 CSS，移除未使用样式 |
| 页面加载时间 | > 3s | 优化字体加载策略 |

### 回滚触发条件
- 视觉回归测试发现超过 5 处严重问题（如颜色反转、布局崩溃）
- 可访问性审计失败，且短期内无法修复
- 用户强烈反对（> 80% 负面反馈）

### 回滚执行步骤
1. 通过 Git 回滚到改造前的 commit
2. 或通过环境变量 `DOCPATH_UI_THEME=obsidian` 切换到旧主题
3. 发布紧急补丁版本
4. 重新评估设计方向，二次改造
