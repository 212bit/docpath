# R-240 风险分析 (risks)

## 风险矩阵

| 风险 | 可能性 | 影响 | 缓解措施 |
|---|---|---|---|
| **R1: 主题匹配误命中** — 同义词子串匹配可能命中无关 ADR（如 topic="状态" 命中所有含 "状态机" 的 ADR） | 中 | 低 | 限制最多 3 条；无匹配时回退到最近 N 条；标题明确标注"主题相关"让 Agent 自行判断 |
| **R2: decisions.jsonl 增长后性能退化** — 当前 75 条线性扫描无问题，但长期增长到 1000+ 条时可能变慢 | 低 | 低 | `gc-decisions` 已有老化归档机制（默认保留 1000 条上限）；且 ADR 匹配仅扫描 retained records |
| **R3: reveal/context 输出 token 膨胀** — 新增 ADR 段占用 token 预算 | 低 | 低 | 限制 3 条 × ~200 字符 ≈ 600 字符（~200 token），在 15000 token 预算内可忽略 |
| **R4: §2.2 降调后文档"不够吸引人"** — 用户可能觉得降调后能力描述变弱 | 低 | 中 | 降调 ≠ 删除能力，只是对齐实际实现；未来实现后可随时升级措辞 |
| **R5: ADR 提取链改动引入回归** — 修改 journal.ts 可能影响现有 ADR 写入 | 极低 | 高 | **不改提取链本身**——仅补测试验证现有行为；可选增加日志不影响逻辑 |
| **R6: context.ts --agent YAML 格式变更** — 新增字段可能破坏下游消费者 | 低 | 中 | append-only 新增字段；`--agent` YAML 消费者应忽略未知字段 |

## 总体风险评估

**低风险**——所有改动均为 append-only 或纯文本修改，不改核心 schema、不改状态机、不改提取链逻辑。最大风险在主题匹配的误命中，但通过限数和回退策略可控制在可接受范围内。
