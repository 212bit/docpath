# DocPath UI Design - Requirements Analysis

## 1. 目标与背景

### 项目背景
DocPath 是一个渐进式文档驱动工作流 CLI 工具，专为大模型 Agent 和人类开发者设计。当前已有基础 Dashboard UI，使用 React + Tailwind CSS 4 + Vite 构建。

### 设计目标
1. **优化现有 Dashboard 体验**：改进当前深色主题 UI 的视觉层次和信息密度
2. **提升可用性**：为多项目管理、任务追踪、门禁监控提供更直观的交互模式
3. **保持 CLI 优先理念**：UI 作为辅助观察工具，不替代 CLI 核心工作流
4. **体现品牌个性**：从工程工具的冷峻黑色转向更温暖、更有辨识度的设计语言

### 用户角色
- **主要用户**：使用 Claude Code 的开发者（人类 + AI Agent）
- **使用场景**：
  - 监控多个项目的 DocPath 工作流状态
  - 查看任务进度、门禁结果、事件时间线
  - 快速定位需要人工介入的阻塞点
  - 理解 worktree 并发开发状态

## 2. 用户/角色/触发场景

### 核心用户旅程
1. **项目总览场景**
   - 打开 Dashboard，快速扫描所有项目健康度
   - 识别 "Attention Queue" 中的阻塞项
   - 点击项目进入详情

2. **单项目深入场景**
   - 查看当前任务的 Phase/Gate 状态
   - 检查 Check/Review 门禁结果
   - 浏览事件时间线，追溯问题发生点
   - 在 Workboard 中操作任务步骤（认领、完成、阻塞）

3. **Backlog 管理场景**
   - 浏览需求池，查看优先级分布
   - 提升 requirement 为可执行任务

4. **Worktree 并发开发场景**
   - 监控多个工作树的活跃状态
   - 管理 session leases，避免状态冲突

### 触发时机
- 开发会话开始时，检查工作流状态
- 门禁失败时，查看具体错误
- 多人协作时，避免并发冲突

## 3. 功能需求矩阵

| 需求 | 优先级 | 验收标准 | 依赖 |
|------|--------|----------|------|
| 应用温暖色调设计系统 | P0 | 使用 warm cream 背景、terracotta 强调色、serif 标题 | 无 |
| 改进项目列表可扫描性 | P0 | 状态点清晰、hover 有微动效、文字层次分明 | 无 |
| 优化 Attention Queue 视觉权重 | P0 | 使用 terracotta 边框高亮、错误态醒目 | 无 |
| Dashboard 页面响应式布局 | P1 | 窄屏下单列堆叠，宽屏下左右分栏 | 无 |
| Workboard 卡片交互优化 | P1 | 拖拽排序、状态切换流畅、加载态友好 | 现有 API |
| 真实照片/插图点缀 | P2 | Hero 区域使用 Unsplash 图片，非必需功能点 | 无 |
| 空态/错误态一致性 | P1 | 所有列表/表格在无数据时显示友好提示 | 无 |

## 4. 非功能需求

### 性能
- 初次加载 < 2s
- 数据刷新 < 500ms
- 动画流畅 60fps

### 安全
- 只读 Dashboard，不直接修改文件系统
- API 执行命令需用户确认（modal）

### 可观测性
- 每次 CLI 命令执行有日志 modal
- 网络请求失败有错误 banner

### 可访问性
- 键盘导航支持
- 对比度符合 WCAG AA
- 屏幕阅读器语义化标签

## 5. 范围边界与明确不做

### 在范围内
- 重新设计现有 7 个页面的视觉风格
- 优化组件库（按钮、卡片、表格、状态标签）
- 改进动画和微交互

### 明确不做
- ❌ 不构建文本编辑器（Spec/Plan 仍通过外部编辑器）
- ❌ 不替代 CLI（复杂操作仍需命令行）
- ❌ 不做实时协作（Dashboard 是单用户视图）
- ❌ 不做移动端适配（桌面优先）
