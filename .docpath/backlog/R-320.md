## 背景

R-317 / S2 已把 `next --agent` 的静态字段瘦身（`gate_policy` 移入 verbose、`recent_decisions` 5→2、`DECISIONS_MAX_LINES` 50→20），单次输出降到 ~1800 字符。但这只压住了"输出长度"，没压住"确认次数"。

`trace.jsonl` 实测 `next`+`status` 合计 **215 次，占 14.3%**，多为纯状态确认。真正的 token 成本不在单次输出，而在于**每一次确认都强制一个"全量历史重注入" turn**：按 \(C(N)=N\cdot B+\delta\cdot N^2/2\)，一次无变化的 `next` 依旧要付 \(B\)（约 15–25k）+ 当时全段历史。若状态相对上一次没变，这一整轮就是**零信息增量**。

方案：为 `next --agent` 增加**状态哈希去重**——
- 计算覆盖所有影响路由字段的快照哈希（`state`、`phase`、活动 `step` 状态、`drift`、`install_health`、`recommended_command`、`exit_criteria`），持久化到 workspace。
- 与上次成功输出的哈希比对：**无变化**时仅返回单行 `{status_unchanged: true, hash, hint: "状态未变；需完整快照加 --refresh"}`；**有变化**时才展开完整 YAML。
- `--refresh`（或 `--verbose`）强制返回完整快照。

安全边界：**宁可漏省、不可误判"无变化"**。哈希必须覆盖任何会改变 `recommended_command`/`exit_criteria`/门禁结论的字段；新增路由字段时必须纳入哈希，否则退回 Agent 会收到过期指令。

## 验收

- [ ] 连续两次状态未变的 `docpath next --agent`：第二次返回单行 `status_unchanged` 且退出码 0，不展开完整快照。
- [ ] 任一影响路由的字段变化（state/phase/step 状态/drift/install_health/recommended_command/exit_criteria）后，`next` 必须返回完整的新快照，绝不返回 `unchanged`。
- [ ] 提供 `--refresh`（和 `--verbose`）绕过哈希、强制全量输出。
- [ ] 在 `tests/next.test.mjs` 覆盖"哈希命中→单行"与"哈希 miss→全量"两条路径；文档/AGENTS 说明 Agent 如何配合去重（不要把"没变化"误读成"命令失败"）。
- [ ] 全量测试与 typecheck 通过，零回归。
