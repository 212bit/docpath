## 背景

诊断发现 DocPath 当前有三组语义需要统一：1) .docpath/tasks/current 现在是 latest/current alias，完成后仍保留最新完成任务内容，但协议未明确它是否只能指活跃任务；2) canonical task evidence 保留在 .docpath/tasks/T-*，历史任务需要手动 docpath gc --force 才归档到 done，完成任务本身不会自动归档；3) status --agent 与 next --agent 当前都复用 generateAgentOutput，agent 输出重复；4) install metadata 和 install_health 只记录单一 target，例如 opencode，但一个项目可能同时安装并支持 Codex、Claude Code、OpenCode。需要明确 runtime alias、canonical evidence、history archive、agent route 和 install adapter set 的边界。

## 验收

AC-1: 明确并实现 tasks/current 语义：active-only 或 latest-task alias 二选一；无论选择哪种，都必须防止 promote 后残留旧任务内容。AC-2: 明确 completed canonical task evidence 与 tasks/done 归档边界；closeout/git evidence 完成前不得自动移动证据路径，完成后应有 gc 提示或安全归档入口。AC-3: current alias 不作为默认 git evidence，docpath changes --agent 只推荐 canonical evidence。AC-4: status --agent 与 next --agent 的 agent contract 去重或分层，status 偏状态快照，next 偏下一步路由。AC-5: install target 从单一 target 语义升级为 installed adapter set 或 universal health，并区分当前会话 agent 与项目已安装适配器。AC-6: 增加回归测试覆盖 current alias completed/promote 行为、gc 候选、multi-agent install health、status/next agent 输出边界。
