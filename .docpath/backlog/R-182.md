# T-DRAFT-data-uniform - 数据统一：消除 MD↔JSON 双向同步，建立 JSON 单真源

## 1. 背景与动机

当前 DocPath 维护了 5 对 MD↔JSON/JSONL 冗余存储（current.md↔state.json, plan.md↔plan.json, spec.md↔spec.json, breadcrumb.md↔breadcrumb.jsonl, docs.md↔docs-index.json），另有 3 个仅有 MD 无 JSON 的文件（last-check.md, review.md, pending-done.md）。

问题：
- 双向同步导致数据漂移，需 SHA256 hash 检测和 --fix-drift 补偿
- structured-docs.ts 的 drift 检测 + task-files.ts 的 sync 逻辑约 300 行，只解决自己造成的问题
- writeActiveTaskFile 每次写入写 4 个文件（spec.md + spec.json + plan.md + plan.json），非原子
- current.md 存 state 冗余，违反 AGENTS.md "JSON 是真源" 的承诺

## 2. 需求清单

### 功能需求

- [ ] FR-1: 补齐 JSON 缺口 — 为 last-check.md / review.md / pending-done.md 创建 JSON 等价文件
- [ ] FR-2: 双写兼容 — Step 1 期间同时写 MD + JSON，读取优先 JSON，JSON 不存在时回退 MD
- [ ] FR-3: 内部切读 — 所有 CLI 命令从读 MD 改为读 JSON/JSONL
- [ ] FR-4: 停止写 MD — writeActiveTaskFile 只写 JSON（不再写 spec.md / plan.md）
- [ ] FR-5: 按需渲染 — docpath render 命令从 JSON 一次性生成 MD 视图
- [ ] FR-6: 清理冗余 — 删除 structured-docs.ts 的 SHA256 漂移检测、detectActiveTaskFileDrift、syncActiveTaskFiles、--fix-drift 参数
- [ ] FR-7: status 直读 state.json — docpath status 不依赖 current.md，直接解析 state.json

### 非功能需求

- [ ] NFR-1: 向后兼容 — 已存在的 .docpath workspace 无需迁移脚本
- [ ] NFR-2: 写入原子性 — JSON 文件写入使用 writeFileAtomic（临时文件 → rename）
- [ ] NFR-3: 性能 — reveal/context 读文档索引从全量 322KB JSON 改为预计算摘要

## 3. 范围界定

### In scope
- .docpath/workspace/last-check.json / review.json / pending-done.json 创建
- CLI 内部所有读路径从 MD 切到 JSON
- writeActiveTaskFile 去掉 MD 写入
- docpath render 新命令
- 漂移检测代码删除
- status 命令不从 current.md 读取
- current.md 仅在 docpath render --view current 时生成

### Out of scope
- rules/*.md、INDEX.md、harness.md、backlog/ 等人类直接维护的 MD
- 工作流状态机本身的改造（phase/gate 合并等）
- 锁机制改造
- token 估算改进

## 4. 关键决策

- D1: plan.json 是真源，agent/用户写 JSON，docpath render 生成 plan.md
- D2: JSONL 保留 append-only 格式，不改为 JSON Array
- D3: docpath status 直接读 state.json，不再读 current.md
- D4: Step 2 的"先读 JSON，回退 MD"模式保留一个 release 周期后移除 MD 读路径
- D5: render 命令输出的 MD 不自动写回文件系统（只 stdout），除非指定 --output
