## 背景

现有 UI 设计序列从 UI Prompt Brief 直接跳到出 Design Preview，缺少「先定前端技术栈→充分讨论→再画图」的前置环节。结果是门禁逼出视觉稿但稿前无框架决策与充分讨论，这正是 Dashboard 不符合预期的根因。需在 UI 设计序列最前插入硬门禁 Framework Decision：选定栈 + ≥1 被否决备选 + 理由。框架 skill 不内置，只做决策记录+加载提示。

## 验收

AC-1: 涉及产品 UI 的任务在 go 前若缺 frontend-stack.md 或其缺少被否决备选/理由，被硬门禁拦截，排在 design-preview 之前; AC-2: frontend-stack.md 模板含选定栈/被否决备选(≥1带理由,纯静态也需写)/约束/待加载skill; AC-3: docpath-design skill 将 Framework Decision 列为序列第一步并含框架讨论提问清单+加载提示; AC-4: 增量UI任务可写「沿用既定栈」通过门禁,exempt路径不变; AC-5: ui-gate/go-ui-gate 测试扩展且全绿
