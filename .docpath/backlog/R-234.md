## 背景

DocPath currently lets backlog/spec flows retain lower workflow profiles even when the work is high-level or explicitly requires a spec. That can let broad workflow, architecture, or agent-behavior changes proceed with gates that are too light. Need a deterministic rule that automatically upgrades the workflow profile to standard when task level, spec requirement, or major-change indicators demand the standard gates.

## 验收

When a backlog item or task is level 2/3, requires a spec, or includes major-change categories such as workflow/agent behavior, architecture/module boundaries, API/data contracts, permissions, or long-term maintenance cost, DocPath resolves the workflow profile to standard. Existing quick/low-risk level 0/1 flows remain unchanged unless one of those indicators is present. Routing, status, plan/go/check behavior, and user-facing hints explain the upgrade reason. Tests cover quick compatibility, level-based upgrade, spec-required upgrade, and major-change upgrade. Because this changes workflow/agent behavior, implementation must include a Decision Brief and explicit user confirmation before go.
