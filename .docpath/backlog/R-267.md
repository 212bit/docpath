## 背景

现有项目接入 DocPath 时，`docpath init` 写入的是模板 `.docpath/rules/architecture.md`、config.yaml 里只填 framework 字符串，既不反映项目真实技术栈与目录结构，也不提取 test/build/format 命令；`docs scan` 默认只扫描 `.docpath/` 内部，外部 README.md/docs/ 无法进索引。

这导致：(1) agent 拿不到"本项目怎么跑测试/构建"的真实命令，只能靠 CLAUDE.md 手填或自我猜测；(2) architecture.md 与真实结构脱节，需事后用 `docpath learn` 从执行经验回流才能补上；(3) 外部项目文档游离在 docs-index 之外，docs-index 易陈旧、检索覆盖不全。

`--scan-existing` 选项让已有项目在 init 时点一次性完成"真实目录结构扫描 → 非模板架构 → 命令提取填充 → 外部文档路径扫描"，实现不迁移/复制文件前提下的一键智能接入。

[现状核实见 .docpath/backlog/analysis/R-267-summary.md；5 件验收逐项 gap 与边界判定在该文件]

## 验收

1. `docpath init` 命令行增加 `--scan-existing`/`-s` 选项。
2. 支持扫描已有项目的代码目录布局，生成非模板化的 `.docpath/rules/architecture.md`（包含真实的目录结构树）。
3. 解析项目主流配置文件（如 `package.json`、`Cargo.toml`、`go.mod` 等），自动寻找测试、构建、格式化命令，填充至 `CLAUDE.md` 和 `.docpath/config.yaml`。
4. `config.yaml` 新增 `document_scan_paths` 字段（默认 `[".docpath/", "README.md", "docs/"]`），且 `docpath docs scan` 支持读取该字段并扫描外部项目文档。
5. 编写针对这些功能的单元测试，保证扫描、提取及写入的一致性。
