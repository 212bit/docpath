# T-20260531-review - 修复 review 提示中的文件名占位符输出

> backlog_id: R-035
> backlog_source: docpath backlog add

## 1. 背景与动机

review 命令在输出 info 级提示时，把文件名前缀误写成了字面量 `[f.file]`，导致审查报告对用户不可追踪。这个问题虽然不影响 exit code，但会直接破坏 review 结果的可读性和定位价值。

## 2. 需求清单

### 功能需求
- [ ] FR-1: review 输出 info 级提示时，必须显示真实文件路径，而不是字面量占位符。
- [ ] FR-2: 自动化测试需要覆盖包含 TODO 提示的 review 输出，防止该格式回归。

### 非功能需求
- [ ] NFR-1: 保持现有 review 命令的审查规则、状态推进和退出语义不变。
- [ ] NFR-2: 修复应局限于输出格式与回归测试，不扩展 review 的检查范围。

## 3. 范围界定

### 包含
- 修复 review info 提示中的文件名渲染
- 为 review 输出补充针对性回归测试

### 不包含
- 重写 review 命令的静态检查策略
- 调整 warn/error 的判定规则

## 4. 关键决策

| # | 决策 | 选项 | 结论 | 理由 |
|---|------|------|------|------|
| 1 | 修复方式 | 只改输出字符串 / 重构 findings 模型 | 只改输出字符串 | 问题是渲染错误，不需要扩大修改面 |
| 2 | 回归保护 | 手工检查 / 自动化测试 | 自动化测试 | 这是 CLI 输出契约，应该有稳定护栏 |

## 5. 验收标准

- [ ] AC-1: 触发 TODO 提示时，review 输出包含真实文件名，例如 `src/commands/review.ts`。
- [ ] AC-2: 不再出现字面量 `[f.file]`。
- [ ] AC-3: 相关测试、全量测试与 `docpath check` 通过。
