## 1. 背景与动机

### 背景与痛点
单纯计算 DocPath 协议本身的注入体积（如 spec/plan/rules）无法反映真实 Agent 开发中的实际 Token 消耗。在真实场景中，80% 以上的上下文消耗和失真发生在**真实工具调用（Tool Calls）**上：例如全量大文件读取（`view_file` 吞噬数千 tokens）、大体量命令输出污染（`run_command` 打印超长日志或全量测试堆栈）、重复读取热点文件、编辑匹配失败反复重试等。必须深入真实会话的工具调用链，建立工具级真实 Token 归因与低效诊断引擎。

### 验收标准
- [ ] AC-1: 实现工具级真实 Token 归因分析（统计每个工具的调用频次、参数及输出真实 Token 消耗、占比分布与错误率）
- [ ] AC-2: 实现真实工具低效与失真诊断器（检测重复读取相同文件、超长命令输出污染、代码编辑失败反复重试、无并发子代理直接深改等）
