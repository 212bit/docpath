# T-20260923-check-scope - check scope 缓存命中时输出明确提示而非静默复用

> backlog_id: R-357

## 1. 背景与动机

改过代码后跑 `docpath check`，scope 缓存命中时直接给 ✅，但底层重 runner（typecheck/build/test/lint）并未实际执行——复用的是上次绿色 check 的结果。复用时仅在开头打一行 `♻️ scope 缓存命中...` 日志，而逐项报告里所有缓存项都伪装成真跑出的 ✅，极易让人误以为本次真的跑过了。

复现（R-056 S8，ferrum）：改过 agent/Cargo.toml、shared/src/staged_tool.rs 后跑 check，报「scope 缓存命中…判定复用」并直接给 ✅；`--no-cache` 强制全量后确实多跑了一次 cargo test。

## 2. 需求清单

### 功能需求
- [x] FR-1: 缓存命中时，逐项报告中每个被复用的检查项须显式标注「（缓存复用，未实际执行）」，不能伪装成真跑的 ✅
- [x] FR-2: 全量 check 末尾保留一行聚合提示，说明本次有多少项来自缓存复用、可用 --no-cache 强制重跑

### 非功能需求
- [x] NFR-1: 仅修改渲染层与缓存结果标记，不改变 scope 缓存的命中/失效判定逻辑

## 3. 范围界定

### 包含
- CheckResult 增加 cached 标记；cache.ts 复用项打 cached: true；evidence.ts 报告渲染在缓存命中时显式提示

### 不包含
- 调整 scope digest 计算或缓存失效策略
- --no-cache 行为变更

## 4. 关键决策

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| 1 | 复用项提示放在逐项报告还是聚合行 | 两者都做 | 逐项提示防误读，聚合行保留总览 |

## 5. 验收标准

- [x] AC-1: 缓存命中时，被复用检查项的报告行不是孤立的 ✅，而是带「缓存复用」标注
- [x] AC-2: 全量报告末尾出现一行说明缓存复用项数与 --no-cache 提示
- [x] AC-3: --no-cache 或真实变更导致全量执行时，报告中不出现「缓存复用」字样（标记不误标）
- [x] AC-4: 现有 check 测试套件（含缓存命中路径测试）不回归
