# T-20260531-fail-loud - 补齐未知位置参数的 fail-loud 校验

> backlog_id: R-034
> backlog_source: docpath backlog add

## 1. 背景与动机

设计文档在 Dogfooding 章节里明确保留了一个后续缺口：当前 fail-loud 只覆盖了“未知命令 / 未知 flag / 缺失必填参数”，但对“命令已匹配后额外塞入未知位置参数”的情况还没有统一拦截。

这会带来两个问题：

- 某些命令如 `docpath status foo` 之类的调用，理论上应立即报错，但当前入口只检查 `!matchedCommand && parsed.args.length > 0`，一旦命令已匹配，多余位置参数可能被悄悄忽略；
- 设计文档也指出 `docs/debug` 等命令当时仍依赖未声明位置参数，需要先统一成 `<action>` 或明确参数声明，否则做全局拦截会误伤已有命令。

当前 `register.ts` 里仍能看到这种混合状态：有的命令显式声明了 `<action>` 或 `[file]`，有的命令则没有位置参数定义，却可能接受多余 token 而不 fail-loud。

本任务聚焦补齐这层 CLI 契约：让已匹配命令收到未声明位置参数时也能稳定报错，同时不破坏那些本来就应该接收位置参数的命令。

## 2. 需求清单

### 功能需求
- [ ] FR-1: 对于未声明位置参数的命令，传入额外位置参数时 CLI 必须 fail-loud，而不是静默忽略。
- [ ] FR-2: 已显式声明 `<action>`、`[file]`、`[id]` 等位置参数的命令必须继续正常工作，不被通用拦截误伤。
- [ ] FR-3: 错误提示需清楚指出多余位置参数及建议的帮助命令。
- [ ] FR-4: 需要新增或增强自动化测试，覆盖典型的未知位置参数场景与合法位置参数场景。

### 非功能需求
- [ ] NFR-1: 保持与现有 DocPath 工作流兼容
- [ ] NFR-2: 不改变命令核心语义，只增强 CLI 参数校验边界。
- [ ] NFR-3: 回归验证需串行执行，避免 `dist/` 清理带来的测试噪声。

## 3. 范围界定

### 包含
- 补齐未知位置参数的 fail-loud 校验
- CLI 入口参数校验
- 与位置参数相关的命令注册 / 测试补强

### 不包含
