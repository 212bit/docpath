# T-20260531-review-dry-run - 补齐 review --dry-run 预览模式

> backlog_id: R-036
> backlog_source: docpath backlog add

## 1. 背景与动机

当前测试和部分工作流假定 `docpath review --dry-run` 可用，但 CLI 实际未注册该选项，运行时会因未知参数直接失败。这导致测试以“只要有输出就算通过”的方式掩盖了命令契约缺口，也让用户无法安全预览 review 结果。

## 2. 需求清单

### 功能需求
- [ ] FR-1: `docpath review --dry-run` 必须成为真实支持的命令选项，能够输出审查结果预览。
- [ ] FR-2: dry-run 模式下不得写入 `review.md`、breadcrumb、决策日志或推进工作流状态。
- [ ] FR-3: 自动化测试必须校验 dry-run 的退出码和无副作用行为，避免再次出现假阳性。

### 非功能需求
- [ ] NFR-1: 非 dry-run 路径的 review 行为、审查规则和状态推进保持不变。
- [ ] NFR-2: dry-run 输出应尽量复用正式 review 的分析逻辑，避免分叉两套规则。

## 3. 范围界定

### 包含
- review 命令注册层补齐 `--dry-run`
- review 实现增加只读预览分支
- 针对 dry-run 的回归测试和副作用校验

### 不包含
- 重写 review 的静态分析规则
- 为 review 引入新的输出格式或 AI 模式

## 4. 关键决策

| # | 决策 | 选项 | 结论 | 理由 |
|---|------|------|------|------|
| 1 | dry-run 策略 | 仅放行参数 / 真正实现只读预览 | 真正实现只读预览 | 测试和用户都需要可信的预览能力，而不是静默忽略参数 |
| 2 | 回归保护 | 只看输出文本 / 同时校验副作用 | 同时校验副作用 | dry-run 的核心契约是不改状态，必须被自动化覆盖 |

## 5. 验收标准

- [ ] AC-1: `docpath review --dry-run` 返回成功并输出审查预览。
- [ ] AC-2: dry-run 运行前后，相关工作流文件不发生写入副作用。
- [ ] AC-3: 目标测试、全量测试和 `docpath check` 通过。
