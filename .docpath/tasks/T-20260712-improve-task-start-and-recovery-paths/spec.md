# T-20260712-improve-task-start-and-recovery-paths - Improve task start and recovery paths

**状态**: 已确认

## 1. 背景与动机

DocPath 在真实使用中最容易打断 Agent 的不是正常路径，而是任务起步和恢复路径：新任务有时会出现半绑定状态，`go`/`agent enter`/`run start` 的边界不够直观，dirty guard 对当前任务变更与无关脏文件的区分也还不够精确。本任务聚焦这些高摩擦点，目标是让任务绑定、恢复和继续执行更稳定、更可预测。

## 2. 需求清单

### 功能需求
- [ ] FR-1: 新任务启动时，任务身份和 canonical 任务目录必须能从单一入口稳定绑定，避免写入 spec 后仍停留在半绑定状态。
- [ ] FR-2: dirty guard 在进入执行步骤时能区分“当前任务相关的工作区变更”和“与当前任务无关的脏文件”，只对后者继续拦截。
- [ ] FR-3: `go`/`agent enter`/相关恢复路径在拒绝时给出更具体的恢复建议，明确何时应使用 `go --step`、何时应使用 `run start`、何时需要清理 dirty worktree。
- [ ] FR-4: 增加回归测试覆盖新任务启动、dirty guard specificity、恢复提示以及相关 failure path。

### 非功能需求
- [ ] NFR-1: 不改变现有命令参数和核心工作流语义。
- [ ] NFR-2: 保留 legacy current.md 迁移和现有状态兼容路径。
- [ ] NFR-3: 不引入新依赖。

## 3. 范围界定

### Decision Brief
- 当前问题: 任务绑定、恢复和 dirty guard 在真实开发里仍会造成半绑定和误拦。
- 目标: 让 DocPath 在“启动新任务”和“从失败/脏状态恢复”时更顺手且更确定。
- 背景: 用户已明确同意优先优化任务启动和恢复路径。
- 可选方案:
  - 方案 A: 新增一键启动命令。
  - 方案 B: 收敛现有入口并改进恢复语义。
- 推荐方案: B。
- 决策理由: 风险更低，能直接改善现有流程，而不引入新的用户心智负担。
- 不做什么: 不改底层状态机模型，不删除 legacy fallback，不新增顶层工作流命令。
- 成本: 局部控制流与提示语改动，以及相关测试补强。
- 风险: dirty guard 范围区分不当可能放松保护或继续误拦；通过测试确保边界正确。
- 回滚方案: 回退本次命令层和 guard 调整。
- 用户确认: 用户已回复“同意，可以进行优化”。
